# In-Memory Stubs

Reads a Go interface definition, emits the structural
skeleton of an in-memory test double with per-method
function delegation (Tier 2) and fault injection (Tier 3).
The developer writes the domain state and default
functions in a companion file.

## go:generate directive

```go
// In example.com/myapp/store/generate.go (or any .go file in the package):

//go:generate testkit stub -o storetest/in_memory_store.gen.go Store
//go:generate testkit stub -o storetest/in_memory_cache.gen.go Cache

// Or combine into one file:
//go:generate testkit stub -o storetest/in_memory_stores.gen.go Store Cache
```

## Default output

`<package>test/in_memory_<subject>.gen.go` (one file per
type when `-o` is omitted)

## What is generated

Given an interface `Store` with methods
`Put(ctx, item) error` and `Get(ctx, id) (string, error)`:

```go
// Code generated by testkit stub. DO NOT EDIT.

package storetest

import (
    "context"

    "go.thesmos.sh/testkit"
    "example.com/myapp/store"
)

// Compile-time interface check.
var _ store.Store = (*StoreStub)(nil)

// StoreOption configures a StoreStub after construction.
type StoreOption func(*StoreStub)

// WithPutFunc overrides the Put method implementation
// (Tier 2: per-method function override).
func WithPutFunc(fn func(context.Context, store.PutRequest) error) StoreOption {
    return func(s *StoreStub) { s.putFunc = fn }
}

// WithPutFault injects a fault that fires every nth
// Put call (Tier 3: fault injection).
func WithPutFault(err error, failEveryN int) StoreOption {
    return func(s *StoreStub) {
        fi := testkit.NewFaultInjector(err, failEveryN)
        s.putFault = &fi
    }
}

// WithGetFunc overrides the Get method implementation.
func WithGetFunc(fn func(context.Context, string) (string, error)) StoreOption {
    return func(s *StoreStub) { s.getFunc = fn }
}

// WithGetFault injects a fault on Get.
func WithGetFault(err error, failEveryN int) StoreOption {
    return func(s *StoreStub) {
        fi := testkit.NewFaultInjector(err, failEveryN)
        s.getFault = &fi
    }
}

// ... one WithFunc + WithFault pair per interface method

// StoreStub is a configurable test double for
// store.Store. Each method delegates to a caller-
// provided function, with optional fault injection.
type StoreStub struct {
    putFunc  func(context.Context, store.PutRequest) error
    putFault *testkit.FaultInjector
    getFunc  func(context.Context, string) (string, error)
    getFault *testkit.FaultInjector
    // ... per method
}

// NewStoreStub creates a stub with one default function
// per interface method plus optional overrides.
func NewStoreStub(
    defaultPut func(context.Context, store.PutRequest) error,
    defaultGet func(context.Context, string) (string, error),
    // ... one arg per method
    opts ...StoreOption,
) *StoreStub {
    s := &StoreStub{
        putFunc: defaultPut,
        getFunc: defaultGet,
        // ...
    }
    for _, opt := range opts {
        opt(s)
    }
    return s
}

// Put checks the fault injector first, then delegates
// to the configured function.
func (s *StoreStub) Put(ctx context.Context, req store.PutRequest) error {
    if s.putFault != nil && s.putFault.FaultShouldFire() {
        return s.putFault.FaultErr
    }
    return s.putFunc(ctx, req)
}

// Get checks the fault injector first, then delegates.
func (s *StoreStub) Get(ctx context.Context, id string) (string, error) {
    if s.getFault != nil && s.getFault.FaultShouldFire() {
        return "", s.getFault.FaultErr
    }
    return s.getFunc(ctx, id)
}

// ... one method per interface method
```

## Injection point

The developer writes a companion file (NOT generated) that
provides the internal state and default implementations:

```go
// storetest/in_memory_store.go — hand-written

type storeState struct {
    mu    sync.Mutex
    items map[string]store.Item
}

// NewInMemoryStore constructs a StoreStub backed by
// in-memory state. The generated NewStoreStub accepts
// one function per method; the domain logic lives here.
func NewInMemoryStore(opts ...StoreOption) *StoreStub {
    state := &storeState{items: make(map[string]store.Item)}
    return NewStoreStub(
        state.put,    // default Put impl
        state.get,    // default Get impl
        state.delete, // default Delete impl
        state.list,   // default List impl
        opts...,
    )
}

func (s *storeState) put(ctx context.Context, req store.PutRequest) error {
    s.mu.Lock()
    defer s.mu.Unlock()
    if _, ok := s.items[req.ID]; ok {
        return store.ErrConflict
    }
    // ... in-memory domain logic
    return nil
}
```

Recording wrappers are generated separately — see
[Recording Wrappers](recording.md).
Some packages need recording without an in-memory stub
(e.g., `recording_publisher.go` wraps the real
implementation to observe calls). Separating the two
generators supports both patterns.

## What is NOT generated

- The default implementation functions (domain logic)
- The internal state struct (e.g., map, slice, mutex)

## Why

The three-tier pattern separates concerns cleanly:

- **Tier 1** (Stub): the generated struct itself — a direct
  test double that forwards calls.
- **Tier 2** (Override): `WithFunc` options let individual
  tests swap one method without rebuilding state.
- **Tier 3** (Fault): `WithFault` options inject
  deterministic failures to test error paths without
  modifying the default implementation.

A test that needs "store where Put fails on the 3rd
call" writes:

```go
b := storetest.NewInMemoryStore(
    storetest.WithPutFault(store.ErrNotFound, 3),
)
```

No mock framework, no interface wrapping, no recording
setup — just constructor arguments.

## Generated tests

For every stub, a companion test file is generated at
`<output_path>` with `_test` appended (e.g.,
`in_memory_store.gen_test.go`). These tests verify the
generated plumbing — not the domain logic.

```go
// Code generated by testkit stub. DO NOT EDIT.

package storetest_test

import (
    "testing"

    "go.thesmos.sh/testkit"
    "example.com/myapp/store/storetest"
)

var errTest = testkit.TestError("stub-test")

func TestStoreStub_DefaultDelegation(t *testing.T) {
    t.Parallel()

    called := false
    stub := storetest.NewStoreStub(
        func(ctx context.Context, req store.PutRequest) error {
            called = true
            return nil
        },
        func(ctx context.Context, id string) (string, error) { return "", nil },
        // ... one no-op per remaining method
    )

    err := stub.Put(t.Context(), store.PutRequest{})
    testkit.NoError(t, err, "default Put must succeed")
    testkit.True(t, called, "default function must be called")
}

func TestStoreStub_WithFuncOverride(t *testing.T) {
    t.Parallel()

    stub := storetest.NewStoreStub(
        func(context.Context, store.PutRequest) error { return nil },
        func(context.Context, string) (string, error) { return "", nil },
        storetest.WithPutFunc(func(context.Context, store.PutRequest) error {
            return errTest
        }),
    )

    err := stub.Put(t.Context(), store.PutRequest{})
    testkit.ErrorIs(t, err, errTest,
        "WithPutFunc override must replace default")
}

func TestStoreStub_WithFaultFiresOnNth(t *testing.T) {
    t.Parallel()

    stub := storetest.NewStoreStub(
        func(context.Context, store.PutRequest) error { return nil },
        func(context.Context, string) (string, error) { return "", nil },
        storetest.WithPutFault(errTest, 2), // fires on 2nd call
    )

    ctx := t.Context()
    req := store.PutRequest{}

    // 1st call: no fault.
    err := stub.Put(ctx, req)
    testkit.NoError(t, err, "1st call must not fault")

    // 2nd call: fault fires.
    err = stub.Put(ctx, req)
    testkit.ErrorIs(t, err, errTest, "2nd call must fault")

    // 3rd call: no fault (fires every 2nd).
    err = stub.Put(ctx, req)
    testkit.NoError(t, err, "3rd call must not fault")

    // 4th call: fault fires again.
    err = stub.Put(ctx, req)
    testkit.ErrorIs(t, err, errTest, "4th call must fault")
}

// ... one DefaultDelegation + WithFuncOverride + WithFaultFiresOnNth
//     per interface method
```

The generated tests use trivial no-op default functions
(return nil/zero) so they exercise the plumbing without
requiring domain state. Coverage target: 100% of the
generated stub code.

## Scale

~40 in-memory impls x ~120 lines = ~4,800 lines generated.
~40 companion test files x ~80 lines = ~3,200 lines generated.
~40 companion files with domain logic remain hand-written.
