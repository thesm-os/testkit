# Codec Test Specs

Reads a proto file, emits a `codectest.Spec[T]` with field
classifications derived from the proto schema.

## go:generate directive

```go
// In the Go package that owns the proto type:
//go:generate testkit codec -o message_codec.gen_test.go ../../api/proto/myapp/types/v1/model/message.proto

// Multiple protos into one file:
//go:generate testkit codec -o codec.gen_test.go ../../api/proto/myapp/types/v1/model/message.proto ../../api/proto/myapp/types/v1/model/event.proto
```

## Default output

`<type>_codec.gen_test.go`

## What is generated

Given a proto message `Message` with fields of various types:

```go
// Code generated by testkit codec. DO NOT EDIT.

package model_test

import (
    "testing"

    "example.com/myapp/codec/codectest"
    "example.com/myapp/model"
)

var specMessage = codectest.Spec[model.Message]{
    Sample: model.Message{
        Value:    []byte("gen-test"),
        Priority: 4, // first non-zero enum value
        Category: "gen-test-category",
        Region:   "eu-west-1",
        Sequence: 7,
    },
    ScalarVarintFields:    []int32{2, 5},
    RepeatedMessageFields: []int32{3},
}

func TestMessage_Codec(t *testing.T) {
    t.Parallel()
    codectest.RunSuite[model.Message](t, specMessage)
}

func BenchmarkMessage_Codec(b *testing.B) {
    codectest.RunBenchSuite[model.Message](b, specMessage)
}

func FuzzMessage_Codec(f *testing.F) {
    codectest.RunFuzzSuite[model.Message](f, specMessage)
}
```

## Field classification

Derived from proto field descriptors:

| Proto type | Spec field |
|-----------|-----------|
| int32/int64/uint32/uint64/sint*/bool/enum | `ScalarVarintFields` |
| fixed32/sfixed32/float | `Fixed32Fields` |
| fixed64/sfixed64/double | `Fixed64Fields` |
| repeated message | `RepeatedMessageFields` |
| map\<K,V\> | `MapFields` |

## Sample value heuristics

| Type | Default |
|------|---------|
| string | `"gen-test-<fieldname>"` |
| bytes | `[]byte("gen-test")` |
| uint32/int32 (enum) | first non-zero enum value |
| uint32/int32 (scalar) | 7 |
| uint64/int64 | 42 |
| bool | true |
| message | recursive sample |
| repeated | 2-element (Grower: 3-element) |

## Injection point

Override the generated spec by creating a hand-written
`_codec_test.go` that shadows the generated variable
name. Or provide a `codec_overrides.go` file with custom
Sample values that the generator reads.

## Why

Codec specs classify proto fields so the test harness can
verify round-trip correctness, field ordering, wire
compatibility, and allocation discipline for every proto
type. Without automation, adding a field to a proto message
requires manually updating the spec's field classification
lists — an error-prone step that the generator eliminates.

## Scale

29 existing specs x ~30 lines = ~870 lines.
