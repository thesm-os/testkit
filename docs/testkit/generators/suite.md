# Conformance Suites

Reads a Go interface definition and its doc comments, emits
a `Run*Suite` function with one subtest per documented
contract guarantee.

## go:generate directive

```go
//go:generate testkit suite -o storetest/store_spec.gen.go Store
//go:generate testkit suite -o storetest/cache_spec.gen.go Cache

// Multiple interfaces into one file:
//go:generate testkit suite -o storagetest/transaction_spec.gen.go Transactor Transaction
```

## Default output

`<package>test/<subject>_spec.gen.go`

## What is generated

Given an interface `Store` with doc comments containing
`# Errors` sections:

```go
// Code generated by testkit suite. DO NOT EDIT.

package storetest

import (
    "testing"

    "go.thesmos.sh/testkit"
    "example.com/myapp/store"
)

// StoreSpec provides the injection points for the
// Store conformance suite. Every implementation provides
// a Factory; the suite exercises the contract.
type StoreSpec struct {
    // Factory creates a fresh, isolated Store instance
    // for each subtest. Must return a ready-to-use Store.
    Factory func() store.Store
}

// RunStoreSuite runs the full conformance suite for a
// Store implementation.
func RunStoreSuite(t *testing.T, spec StoreSpec) {
    t.Helper()

    // --- Happy path ---

    t.Run("Put/valid item succeeds", func(t *testing.T) {
        t.Parallel()
        s := spec.Factory()
        err := s.Put(t.Context(), store.PutRequest{
            ID:   "item-1",
            Data: []byte("x"),
        })
        testkit.NoError(t, err, "Put with valid item must succeed")
    })

    t.Run("Get/returns empty for missing key", func(t *testing.T) {
        t.Parallel()
        s := spec.Factory()
        val, err := s.Get(t.Context(), "missing")
        testkit.NoError(t, err, "Get on missing key must succeed")
        testkit.Equal(t, val, "", "Get on missing key must be empty")
    })

    // ... one happy-path subtest per method

    // --- Error sentinels (from # Errors doc sections) ---

    t.Run("Put/duplicate key returns ErrConflict", func(t *testing.T) {
        t.Parallel()
        s := spec.Factory()
        req := store.PutRequest{ID: "dup", Data: []byte("x")}
        _ = s.Put(t.Context(), req)
        err := s.Put(t.Context(), req)
        testkit.ErrorIs(t, err, store.ErrConflict,
            "Put with duplicate key must return ErrConflict")
    })

    t.Run("Delete/missing key returns ErrNotFound", func(t *testing.T) {
        t.Parallel()
        s := spec.Factory()
        err := s.Delete(t.Context(), "missing")
        testkit.ErrorIs(t, err, store.ErrNotFound,
            "Delete with missing key must return ErrNotFound")
    })

    // --- Idempotency ---

    t.Run("Get/idempotent on missing key", func(t *testing.T) {
        t.Parallel()
        s := spec.Factory()
        val1, _ := s.Get(t.Context(), "missing")
        val2, _ := s.Get(t.Context(), "missing")
        testkit.Equal(t, val1, val2, "Get must be idempotent")
    })

    // --- Nil/empty input ---

    t.Run("Put/empty data does not panic", func(t *testing.T) {
        t.Parallel()
        s := spec.Factory()
        _ = s.Put(t.Context(), store.PutRequest{
            ID: "empty",
        })
        // no panic = pass
    })

    // --- Concurrent safety ---

    t.Run("Get/concurrent reads do not race", func(t *testing.T) {
        t.Parallel()
        s := spec.Factory()
        testkit.ConcurrentStress(t, 8, 50, func(g, i int) {
            _, _ = s.Get(t.Context(), "key")
        })
    })
}

// RunStoreBenchSuite runs per-method benchmarks.
func RunStoreBenchSuite(b *testing.B, spec StoreSpec) {
    b.Helper()

    b.Run("Put", func(b *testing.B) {
        s := spec.Factory()
        req := store.PutRequest{
            ID:   "bench",
            Data: []byte("bench"),
        }
        for b.Loop() {
            _ = s.Put(b.Context(), req)
        }
    })

    // ... one benchmark per method
}
```

## Contract directives

The generator reads `//testkit:` directives on interface
methods to determine which mechanical subtests to emit.
Directives are machine-readable, grep-able, and lint-able
— the generator warns on unknown directives. Doc comment
`# Errors` sections remain as human documentation; the
directives are the machine contract.

| Directive | Subtest category | Description |
|-----------|-----------------|-------------|
| `//testkit:errors ErrX ErrY` | Error sentinels | One subtest per listed sentinel |
| `//testkit:idempotent` | Idempotency | Repeat call, assert same result |
| `//testkit:concurrent` | Concurrency safety | Parallel calls, assert no race |

Directives are per-method. Happy path and nil/empty input
subtests are always generated for every method.

Example:

```go
//testkit:errors ErrConflict ErrNotFound
//testkit:idempotent
//testkit:concurrent

// Put persists an item to the store.
//
// # Errors
//
//   - [ErrConflict]: duplicate key.
//   - [ErrNotFound]: referenced resource does not exist.
func (s *Store) Put(ctx context.Context, req PutRequest) error
```

This produces: happy path, nil input, two error sentinel
subtests, an idempotency subtest, and a concurrency
subtest — six subtests total for `Put`.

A method without `//testkit:idempotent` or
`//testkit:concurrent` gets only happy path, nil input,
and error sentinels. This prevents generating vacuous
tests for methods where those guarantees don't apply.

The `//testkit:errors` directive lists sentinel names by
their exported identifier. The generator resolves them
to the package's `Err*` variables at generation time and
errors if a name doesn't match an exported error.

## Injection point

Every implementation wires its conformance suite in one
test function:

```go
// postgres_test.go — hand-written

func TestStore_Conformance(t *testing.T) {
    pool := sharedPool(t)
    storetest.RunStoreSuite(t, storetest.StoreSpec{
        Factory: func() store.Store {
            return postgres.NewStore(pool)
        },
    })
}
```

## What is NOT generated

- Domain-specific subtests beyond the mechanical contract
- The `Factory` implementation
- Complex setup scenarios (multi-step test state)

## Why

Conformance suites are the primary test battery — every
implementation of an interface must pass the same suite.
When the interface contract evolves (new error sentinel,
new idempotency guarantee), the suite regenerates and every
implementation is automatically tested against the new
contract. No implementation can silently skip a test.

## Scale

109 existing files x ~100 lines = ~10,900 lines.
